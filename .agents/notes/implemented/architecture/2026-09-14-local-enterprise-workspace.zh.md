# Agent Note: 本地企业空间的数据归属

Status: implemented

[English](2026-09-14-local-enterprise-workspace.md) | 中文

## Problem

企业档案和可复用媒体需要独立于智能体会话的持久化归属。

## Decision

[企业插件](../../../../trade/enterprise/README.zh.md) 提供原生侧栏、主面板插槽和认证后的 Connection 路由。SQLite 保存一个档案和资料元数据；私有文件使用 UUID 寻址，仅在流式写入和内容校验完成后发布。删除时在事务中清空对应标识引用。[底座决策](../process/2026-09-14-trade-workspace-foundation.zh.md) 继续负责上游组合和本地部署，本记录负责企业持久化。

## Alternatives considered

**独立 GEO 应用或固定建档表单。** 建档属于现有聊天。内置 skill 负责提问顺序，SQLite 保存动态企业和产品草稿。入口按钮调用原生 skill 加载器；聊天提问服务针对精确的已保存版本取得用户确认。这保留了用户审核，同时不把行业字段写入应用数据结构。

**把聊天附件作为企业资料库。** 附件凭据属于智能体请求。上传企业资料不能将其加入模型上下文。

**立即增加账户和对象存储。** 单个本地企业没有成员或分享需求。额外服务不能消除档案与资料归属规则的实现工作。

## Consequences

结构化产品事实及引用它们的报价由草稿统一保存。独立的用户事实核验凭据仅允许生成需要认证、禁止索引的 HTML 和 JSON-LD 预览，两种输出使用同一组事实。普通建档确认不能产生该凭据；每次预览都会重新检查来源、冲突及有效期。将内部确认视为公开就绪会暴露未核验的商业声明，并将认证路由误报为可抓取。因此，公开部署与发现能力始终明确标为未完成。

这是单个企业，不提供租户隔离。账户体系需要在每个记录和文件路由实施授权。不支持的 SQLite 版本明确报错；启动时清理中断或无归属文件。媒体锁定可能使物理删除延迟到重启。真实 Connection 组合测试覆盖持久化、校验、范围读取和上传销毁。浏览器测试使用真实 dsh profile 和隔离数据。原生 skill 调用测试验证指令加载。建档 skill 与工具改变模型输入但不改变会话格式；完整真实模型及录制会话建档测试尚未覆盖。
