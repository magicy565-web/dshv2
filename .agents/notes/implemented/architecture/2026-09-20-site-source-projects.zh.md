# Agent Note: Site source projects independent of commerce

Status: implemented

[English](2026-09-20-site-source-projects.md) | 中文

## Problem

Workspace 网站需要跨会话保留可编辑源码和二进制资源。强制 Shopify 连接且只存储页面标题，会阻止独立网站的创建和维护。

## Decision

Site 服务保存不可变源码项目版本，销售连接为可选项。静态项目构建为关联明确版本的确定性文件产物。Next.js 源码可以存储但不执行；运行前必须具备隔离的框架构建提供方。源码解析拒绝不安全的跨平台路径、凭据文件名和无效二进制编码。

企业部署负责站点存储和可信租户身份。站点工具支持创建项目、读取指定版本、校验版本后修改文件、预览静态项目和恢复草稿。工具输入和结果进入现有工具调用 Session 日志。私有预览仅编译虚拟项目文件，并在不透明来源沙箱中运行浏览器代码；编译器不解析 Host 文件或 Host 依赖。

静态编译保留响应式图片候选、内联 CSS 资源、条件样式和延迟脚本执行时序，让不同视觉设计使用普通浏览器能力。入口解析使用选定的已保存路径，即使 esbuild 因为同路径存在 Host 文件而改写路径文本也不受影响。嵌入页面的导航通过当前 iframe 向父页面发送消息，因为不透明来源请求无法直接通过编辑器鉴权。父页面保留站点和版本，只切换请求的页面，不授予同源访问。编译诊断只标识项目文件，不包含 Host 调用栈路径。浏览器夹具覆盖三种视觉风格、响应式布局、交互和导航；独立的真实模型验收命令在 Agent 进程退出后检查生成源码。缺少凭据时跳过真实验收，不将跳过计为成功。

独立托管分别记录源码版本和提供方构建。企业使用方采用可替换的提供方接口及独立 SQLite 记录。Vercel 提供方使用受保护的部署地址构建正式环境版本，并关闭域名自动分配。人工发布确认绑定现有构建和源码摘要，因此后续草稿修改不会改变被发布的内容。提交成功不表示正式路由已切换：只有查询提供方确认后才更新线上记录。未确认的提交保留检查点，并按请求标识和摘要查询恢复，不重复提交。

下线暂停提供方项目，不删除部署；恢复上线保留正式构建。可用状态和域名修改先持久化请求，再联系提供方，并通过刷新状态核实未确认的响应。域名确认绑定观察到的托管记录版本。所有权验证和 DNS 路由分别记录，因为证明控制域名并不表示访问者已能到达网站。

手动导入的资源进入版本化项目，不放入单独的可变资源目录。因此，替换文件只影响新版本，历史预览仍保留原有字节。编辑器检查编码后的版本请求大小，因为二进制转为 base64 后的增长量和已有源码共同占用 Host 限额。ZIP 导出保留普通相对文件名，让源码在平台之外仍可使用。

制造业起始模板以普通已保存源码提供经过审阅的多页设计。编辑器创建与 `site_create` 使用同一项目和版本服务，因此定制、预览和导出保持现有行为。单靠提示词无法保证产品目录和询盘路径的一致性。示意图片和示例企业信息均明确标注；真实联系渠道配置前，询盘只生成本地草稿。大小验证先于站点创建。浏览器验证覆盖全部十页的桌面和手机布局、产品筛选、跨页产品选择，以及未发送的询盘草稿。

模板生成由 Site 包的提供方注册表负责。企业部署提供制造业实现并注册明确版本；编辑器与模型消费者共用输入 schema 和渲染器。源码内的记录保存解析后参数、提供方版本和生成文件摘要。重新组合会拒绝已修改源码，而不是尝试从任意 HTML 推断丢失的组件结构。提供方升级不影响已保存源码；提供方缺失时禁止重新生成，但仍可预览和导出。这一设计明确放弃自动模板迁移和人工改动合并。站点与首个版本在同一存储事务中创建，因此提交失败不会暴露空模板站点。

Next.js 工具预览对每个已保存版本只提交一次，后续调用查询同一部署。构建查询独立于正式路由和 DNS 查询，因此域名服务不可用不会阻止草稿审阅。工具结果区分构建中、失败、未确认和预览就绪状态。发布仍需人工单独审阅现有构建。

构建失败和诊断可用性分别记录。即使日志接口失败，提供方仍返回已确认归属的构建错误摘要，日志可用后再持久保存受限长度的末尾片段。缺失诊断可以重新查询，不重复构建。这既保留修复源码所需的信息，也避免把已确认失败误判为提交结果不明。

[Shopify 能力决策](2026-09-15-shopify-site-capability-seams.zh.md) 继续负责销售提供方分离和发布任务。[销售功能完成提案](../../proposed/architecture/2026-09-15-shopify-site-completion.zh.md) 面向可选销售层，不将销售连接作为独立网站的前提。

欢迎页动画以同一个持续存在的示例网站贯穿修改、预览、文件传输、版本恢复和发布。动画控件不具备源码或托管操作权限：示例成功标记不会更新持久化记录。这一分离允许连续演示产品，而不将示例误认为已保存预览或发布回执。手动选择章节和减少动态效果偏好提供静态画面；自动播放在发布章节后停止。浏览器验证覆盖播放、暂停、网站元素持续存在、减少动态效果、手机布局以及不发生站点修改。

自托管发布独立于草稿指针保存已编译 HTML，通过现有 Host 端口的公开路径前缀提供访问。独立持久化代次保护固定构建发布和下线变更。公开页面保留不透明来源 CSP 沙箱，禁止原生表单跳转，脚本请求可以访问该网站的公开询盘接收器，以及[开源增长决策](2026-09-21-site-open-source-growth.zh.md)管理的可选接口。这样可以在本地使用并通过反向代理托管，同时不授予生成代码已认证编辑器的来源权限。它不会将本地项目传输到另一台服务器。

企业资料导入通过最新内容摘要绑定人工检查，仅投影当前可发布的产品事实和公开已核验资质，并把最终参数保存在模板来源记录中。询盘属于公开输入而不是模型指令：受限 JSON、保留的请求标识、每站配额和私有收件箱将接收回执与邮件投递分开。只有 SQLite 提交后才返回回执。浏览器证据覆盖匿名访客，以及接收后响应丢失；重试仍保留单条记录。


## Alternatives considered

**继续强制 Shopify。** 放弃，因为企业网站、游戏和内部应用可以没有店铺，其源码生命周期属于 Workspace。

**在企业 Host 执行生成的构建脚本。** 放弃，因为 Host 持有企业文档和服务凭据。静态预览编译只解析虚拟文件；服务端框架构建需要单独执行环境。

**只存储生成的 HTML。** 放弃，因为可编辑模块和二进制资源必须支持历史比较和恢复。源码项目和构建产物使用不同表示。

**发布时重新构建最新草稿。** 放弃，因为结果可能与已检查的预览不同。待发布的正式环境构建在提升或回滚时保留部署标识。

**重试每个失败的云端请求。** 放弃，因为响应丢失可能发生在外部成功接受请求之后。持久检查点避免网络故障或进程重启后重复提交。

## Consequences

SQLite 恢复、版本比较和回滚均保留项目文件。仅 Shopify 发布操作会因缺少销售连接失败。单元测试和企业 Host 测试覆盖源码保留、过期编辑拒绝、预览隔离及工具清理。提供方测试覆盖构建、明确构建发布、可用状态、域名、并发和恢复；浏览器测试使用保存的源码及模拟云端响应验证托管操作。云端凭据保留在部署配置中，不进入生成源码。Vercel 集成仍需实际账号验证，包括 DNS 和 TLS；访问权限、应用密钥和持久应用数据仍未完成。本地测试不能证明完整 Sites 产品或真实云发布成功。
