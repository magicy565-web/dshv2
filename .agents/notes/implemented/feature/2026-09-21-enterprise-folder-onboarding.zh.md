# Agent Note: 企业文件夹建档与产品归属

Status: implemented

[English](2026-09-21-enterprise-folder-onboarding.md) | 中文

## Problem

关键词搜索无法证明企业文件夹已被完整处理。上传文件和建立产品记录也代表不同的用户工作：保存目录文件不会创建其中的产品，展示卡片也不拥有产品修订记录。

## Decision

[企业插件](../../../../trade/enterprise/README.zh.md)在传输浏览器选中的文件之前保存导入清单。相对路径保留资料分组，不授予文件系统访问权限。每次上传在同一个 SQLite 事务中保存文件元数据、提取片段和清单回执。重试已完成上传时返回已有回执。部分失败的批次保留成功项，并允许明确重新选择原文件夹续传。达到文字数量限制时产生截断标记，不声称已完整读取。

现有建档会话使用来源工具列出清单、分页读取并保存处理结论。只有已经返回的片段才计入阅读记录。标记为已使用的文档必须读完所有提取片段，且不能存在截断。未知媒体、解析失败和冲突保留为明确缺口。最终人工范围确认包含排除项目，并拒绝用户审阅期间发生的变化。资料导入和删除会使完成标记失效。

产品中心编辑已有 GEO 记录，并关联私有素材标识。修改已确认记录时创建修订草稿，比较预期版本并保留内容历史。归档和恢复作用于整个修订链；活跃发布会阻止归档。描述信息项保持动态，结构化声明保留原有 Agent 编辑路径。确认不授予事实核验或发布权限。

准确的索引引用会把来源文件关联到草稿，并在草稿回执中返回；引用标记存在歧义时必须显式提供文件 ID。缺少面向发布的结构化身份信息时，内部档案仍通过有来源的信息项保存已知事实。未知的选填网址省略，格式错误的网址返回具体字段的校验错误。进度指标要求已阅读资料或明确排除，并审阅当前档案或已确认范围；上传文件或仅确认一家企业都不会完成这些步骤。

[企业数据归属决策](../architecture/2026-09-14-local-enterprise-workspace.zh.md)与[工作台导航决策](2026-09-21-trade-workspace-product-design.zh.md)继续有效，分别负责存储与原生组合。本决策增加文件夹覆盖检查和产品维护，不替代这些归属。

## Alternatives considered

**全部上传后只按关键词搜索。** 搜索可能遗漏相关文档，也无法区分未读文件与不存在的业务事实。持久清单和明确处理结论让缺口可以审阅。

**允许建档任意访问文件系统。** 浏览器选择的文件夹能提供所需资料，同时防止文档指令调用文件系统操作或绕过人工确认。

**为界面建立独立产品数据库。** 这会把产品身份、审阅和来源与 Agent 使用的记录分开。共用 GEO 数据归属保证手动编辑和对话修改一致。

## Consequences

文件夹导入和产品维护可以在模型推理之前或独立于推理执行。文档保持私有，只通过明确工具读取。阅读回执证明片段已返回，不证明模型理解。OCR、视觉理解和压缩包提取尚不可用；这类文件需要文字版或明确排除范围。浏览器不会持久保留文件系统访问许可，因此刷新后续传需要重新选择本地文件。

Host 测试覆盖阅读范围、重启持久化、来源限制、缺失来源、产品修订和确认。真实 dsh Web 测试覆盖桌面及手机上的文件夹选择和产品管理。无密钥 Session 回放覆盖空来源说明、建档指令和文档关联的持久保存。可选的真实模型浏览器用例导入虚构企业与两款产品文档，检查提取事实及未知项，由测试用户完成三次档案审阅及最终范围确认，并检查刷新后的持久化。这不证明任意产品目录的提取准确性或大型文件夹的跨文档冲突处理能力。
