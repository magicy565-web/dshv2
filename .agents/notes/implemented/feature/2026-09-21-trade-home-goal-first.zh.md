# Agent Note: Trade 首页是目标简报，配合工作流、决策队列与成果时间线

Status: implemented

[English](2026-09-21-trade-home-goal-first.md) | 中文

## Problem

企业工作空间首页过去是一面指标墙：四张记录数量卡、三张操作卡、一个任务列表和一张资料卡，全部以相同的视觉权重放在带边框的盒子里。它回答的是"存了什么"，而不是企业负责人打开工作空间时想问的——我们要达成什么、此刻什么在推进、哪里需要我。空状态是一个归零的仪表盘，已完成的工作不可见，整个页面读起来像后台管理台，而不是 AI 原生的经营工作空间。

## Decision

`trade/enterprise/src/client-overview.tsx` 把首页渲染为以排版主导的区域，全部从现有快照派生；后端数据与 API 不变。

1. **目标简报** —— 当前业务目标（截止最近的推进中目标，否则取最近更新的目标）是页面唯一的视觉中心，落在全屏唯一的填充面上：一块墨色使命面板，承载眉题、状态徽章、展示级标题、成功标准、事实性上下文（经现有 `businessGoalTaskCount` 文案的关联任务计数、期限、时间进度条）和一个大号等宽倒计时数字。不从任务完成数推导目标达成百分比；目标编辑器已经确立了由负责人确认达成的语义。首次进入提示与无目标横幅复用同一面板，页面始终只有一个主角。
2. **工作流** —— 进行中的任务与管道中的机会（研究中、已确认匹配、已联系、洽谈中）渲染为台账行：执行者字标（进行中时带脉动环）、状态胶囊、相对日期和目标关联。行点击导航到所属标签页。
3. **决策队列** —— 受阻任务、等待确认的 GEO 档案草稿（由 Agent 创建时标注"AI 整理"）、文字提取失败的文件和新线索，以琥珀色标记呈现，区块标题带计数。
4. **成果时间线** —— 已完成任务及其记录的结果、已成交机会和已确认档案排在一条纵向时间线上，最新在前。

没有目标、没有推进中工作、没有待处理事项且没有成果的工作空间，渲染一个居中的"创建第一个目标"提示，附"先整理企业资料"的次要链接。有数据但没有目标时改为紧凑的目标横幅。没有内容的区块保持安静：成果时间线在首个成果出现前隐藏。

样式在 `workbench-style.ts` —— 每屏一个填充主角面，其余全部用发丝级分隔线和开放区块，行悬停时显现方向箭头，`prefers-reduced-motion` 下关闭动效。面板颜色取自主题的文字与画布令牌，深色模式下自然反转，不写死颜色。文案在 `workbench-locales.ts`，中英文键一一对应。

## Alternatives considered

- **给指标墙换皮** —— 否决：存储记录的计数回答不了任何业务问题，等权重的卡片正是产品方向所禁止的卡片汤。
- **从关联任务完成度推导目标进度** —— 否决：业务目标模型刻意把任务活动与目标达成分开（`businessGoalTaskCount` 只是上下文，结果由负责人记录），计算出的百分比会歪曲这一区分。
- **对话优先的首页** —— 否决：助手只隔一个标签页；首页的职责是定位——目标、推进、决策、成果——而对话框会把页面中心拉回"发指令"而不是"经营"。

## Consequences

首页用工作空间已有的数据回答三个定位问题，空状态是单一动作而不是归零的仪表盘，每一行都能进入所属视图。放弃的是：记录、资料、机会和任务的总量不再出现在首页，它们留在各自的标签页。`workbench.spec.ts` 与 `workbench-empty` 基线已按新行为重写，并通过企业 API 向真实服务器播种后抓取了桌面端、移动端和首次进入的视觉证据。

## Testing

`trade/enterprise/test/workbench.spec.ts` 覆盖目标简报的推进中与已暂停状态、工作流的纳入规则、决策队列的四种条目、成果时间线、行到标签页的导航，以及双语的首次进入快照。
