# Agent Note: Trade MCP 供应商建档

Status: implemented

[English](2026-09-21-trade-mcp-intake.md) | 中文

## 问题

供应商需要通过外部助手建立持久化企业和产品档案，无需再配置一套模型运行时。本地 Skill 和 HTTP 脚本无法提供可发现的 MCP 工具，也不能跨对话保留明确的建档提交范围。

## 决策

[Commerce](../../../../trade/commerce/README.zh.md#mcp-onboarding) 使用官方 SDK 在 `/mcp` 提供无状态 Streamable HTTP。每个请求验证服务端绑定的供应商 Agent 凭据。Host 和 Origin 白名单保护接口；公网部署负责 HTTPS、账号开通和额度。MCP 适配层共用 Commerce 的授权、版本检查、事务和幂等回执，不能声明人类身份，也不能确认事实、授权共享或发布。

不可变来源文字与确切提交范围独立于对话保存在业务数据旁。草稿写入引用本企业来源中的片段，创建关联证据，并将修改值保存为私有、未核验事实。批次失败回滚其中所有产品。来源标记不触发文件读取或网址请求。即使片段匹配，客户端提交的文字仍是不可信资料。

提交记录企业版本及明确选择的产品版本。名称必须有来源，选填商业事实可以缺失。修改草稿或添加资料会清除提交；其他业务操作后，由当前版本和仍有效的名称证据决定提交是否仍有效。客户端负责对话历史、文档提取和建议值的准确性。

[Commerce 归属决策](../architecture/2026-09-21-commerce-business-runtime-separation.zh.md) 继续有效：MCP 写入 Commerce 记录，不替换企业空间 GEO 存储、运行时提供方或商业审批规则，其分离理由没有被取代。

## 考虑过的替代方案

**通过一个通用工具开放全部业务命令。** 封闭的建档工具目录为外部 Agent 提供聚焦的输入结构，并从工具发现中排除特权操作；业务服务仍独立执行权限检查。

**只在 MCP 会话中保存进度。** 无状态请求与持久化业务回执支持重连、重启和重试，无需把记录归属绑定到传输会话。

**由服务端打开客户端路径或抓取任意来源网址。** 显式提交文字让客户端负责文件选择，避免赋予来源标记服务端文件系统或网络权限。二进制导入不属于该传输。

## 后果

官方客户端协议测试覆盖有来源的企业及产品建档、确切提交、数据库重开、重试冲突、批次回滚、来源撤销和跨供应商拒绝。所有者本地的工具目录检查发现文案和注解；[录制的 Harness 会话](../../../../snapshots/session/trade-mcp-empty/session.v3.jsonl) 检查真实 MCP Consumer、发现的 Schema 和模型可见上下文。构建后的 Next.js 路由通过 HTTP、私有数据库及系统分配端口验证。Workbuddy 界面兼容性、真实提取、自助身份体系和公网部署仍需分别接入；本地协议检查不证明这些工作已经完成。
