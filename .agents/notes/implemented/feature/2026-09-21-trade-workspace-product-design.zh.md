# Agent Note: Trade 工作台导航与业务状态

Status: implemented

[English](2026-09-21-trade-workspace-product-design.md) | 中文

## Problem

日常企业工作涉及企业档案、资料、买家机会、任务、网站和已连接电脑。企业展示页和功能演示无法告诉回访用户当前有哪些资料、哪些事项需要处理。独立设计的面板也会削弱这些业务属于同一工作台的感受。

## Decision

已有企业档案时，[企业面板](../../../../trade/enterprise/src/client.tsx)默认打开工作台概览。概览由目标简报、工作流、决策队列和成果时间线组成，全部派生自已保存的企业记录；其呈现方式由[首页目标优先决策](2026-09-21-trade-home-goal-first.zh.md)记录。企业展示保留为独立标签页，继续提供来源详情和维护入口。空工作台说明下一项可执行操作，不使用示例企业、业务结果或虚构绩效指标填充缺失记录。

企业记录、网站和已连接电脑共用排版、间距、界面层次及交互状态。主要控件直接描述业务操作。网站展示静态创建指南和可执行的创建控件。已连接电脑优先展示保存的设备与任务，演示默认折叠，连接管理按需打开。部署通过原生侧栏插槽提供标识，保留现有应用导航与会话服务。

交互反馈区分选中状态、键盘焦点和进行中的请求。短过渡保持视觉连续，不暗示服务端尚未报告的进度。手动刷新与后台轮询分别处理反馈，避免定期更新反复吸引注意。减少动态效果偏好保留状态和文字反馈，同时停用动画。键盘切换标签时，焦点保留在选中的控件上。

可按需使用的 [FORM 组件集](../../../../trade/enterprise/README.zh.md#可复用设计组件)将可复用 React 展示与业务操作分开。CSS 变量限制在 `.td-root` 内，本地化文案与操作回调由调用方提供。离线预览拥有虚构示例与临时交互状态，生产记录和确认权限仍由现有模块负责。预览布局样式与可复用样式分开，因此导入卡片不会替换应用外壳或主题。

[建档向导](../../../../trade/enterprise/src/client-onboarding.tsx)位于 Assistant 内，根据已保存来源和已审阅记录呈现进度卡片。空企业直接打开向导。打开向导不会发送模型请求。用户主动进入对话时，继续已持久化的建档会话；界面上的完成状态不能替代用户审阅及范围确认。

[供应商阅读决策](2026-09-20-supplier-profile-reading.zh.md)、[企业数据归属决策](../architecture/2026-09-14-local-enterprise-workspace.zh.md)与 [Commerce 数据归属决策](../architecture/2026-09-21-commerce-business-runtime-separation.zh.md)继续有效。本呈现决策不改变记录归属，也不改变确认、分享和发布所需的批准。

## Alternatives considered

**继续以企业展示页作为工作台首页。** 展示页说明企业提供什么，但日常工作也需要查看已保存任务、来源和机会。独立标签页保留其阅读用途，工作台概览则支持回访用户开展工作。

**加入示例业务指标填满仪表板。** 示例营收、转化和增长数值会暗示工作台并不掌握的事实。现有记录的数量与状态已经具有参考价值，无需引入缺少依据的商业声明。

**替换上游应用外壳。** 原生插槽已经支持部署标识和业务面板。替换外壳会重复实现会话、认证和导航行为，却不能改善业务记录本身。

**为每个新组件复制页面专用样式。** 副本的焦点、状态和主题行为容易出现差异。作用域内的变量与可组合组件提供共用的展示方式，无需把业务状态移入设计库。

## Consequences

用户获得一致的起点，详细业务操作仍由现有模块负责。概览反映本地保存记录，不代表商业核验、租户隔离或实时服务健康状态。响应式布局、键盘访问、空状态和现有编辑流程需要浏览器验证；外观本身不能证明模型请求或外部服务成功。

组件预览构建为单个离线 HTML 文件。浏览器检查覆盖资料筛选、核对状态、原生弹窗关闭与焦点返回、输入错误、双主题和双语、减少动态效果及窄屏溢出。预览不发起企业请求；业务页面采用组件时，仍需保留该页面已有的持久化与批准检查。
