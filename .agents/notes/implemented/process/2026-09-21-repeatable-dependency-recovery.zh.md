# Agent Note: 可重复的依赖修复与脱敏凭据扫描

Status: implemented

English | [中文](2026-09-21-repeatable-dependency-recovery.zh.md)

## 问题

此工作区包含原生依赖和多阶段构建，因此修复检出目录需要手工执行多条命令。不带 `.git` 元数据的源码包还会在计算客户端构建元数据时延迟失败。检查已停用的提供方名称时，需要包含被忽略的本地环境文件，同时不能让命令输出暴露密钥值。

## 决策

根目录脚本提供三项可重复操作：

- `deps:refresh` 先运行 `pnpm install --frozen-lockfile`，再运行 `pnpm rebuild`；当包存储或工作区链接需要替换时可使用 `--force`。
- `build:archive -- --commit <hex-id>` 使用显式提供的 7–40 位十六进制源码标识调用正常的完整构建；它不会为源码包自行编造 commit 值。
- `security:scan` 接受重复的 `--term` 参数，扫描仓库文件（包括被忽略的 `.env`），并排除生成的依赖目录和构建目录。`security:fastai` 提供已停用提供方的关键词。结果只包含相对路径和行号，不包含匹配行或值。

## 考虑过的替代方案

**手工执行安装、重建和构建命令**没有共享入口，容易漏掉原生依赖修复，因此不采用。

**为源码包静默生成合成 commit**会让构建元数据看起来像真实仓库版本，即使它并非仓库修订，因此源码包构建要求外部标识。

**打印凭据扫描的匹配行**会让本地审计本身成为潜在的密钥泄露源，因此扫描器只报告位置。

## 后果

常见修复路径变为一条命令，同时仍以锁文件作为依赖权威来源。源码包构建明确表达来源，并继续兼容现有的完整构建记录。专项扫描可以安全检查本地被忽略配置，但它是关键词检查，不是完整的密钥检测产品；更广泛的提供方审计需要传入各自的关键词。
