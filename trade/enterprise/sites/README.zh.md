# 自托管企业官网

[English](README.md) | 中文

## 摘要

Sites 工作空间根据已检查的企业资料创建官网，在现有 Host 端口发布固定静态版本，并把访客询盘保存在私有收件箱。本地发布不需要 Vercel。在企业服务器运行同一部署即可提供相同路由；当前没有配置向另一台服务器自动上传或建立隧道。

## 企业内容

选择**读取并检查企业资料**，检查投影出的事实和联系方式，再确认允许将其用于公开官网。创建时会与最新投影的摘要比较；资料发生变化后需要重新检查。初始网站仍为私有草稿。企业名称、简介、业务和联系方式来自已提交的档案。产品需要已确认的 GEO 记录、有效的人工事实核验和通过的产品就绪检查；已确认的新记录会排除其取代的旧记录。仅纳入公开产品事实，不输出私有证据路径。企业资质仅使用公开、已核验且未过期的字符串事实。产品或资质缺失时显示联系指引，不添加示例事实。布局标签支持中英文，公开内容按语言单独审核。本地模型翻译生成可编辑草稿，语言导航和 hreflang 只链接已有的对应页面。

已安装的 `company-manufacturing@3.0.0` 提供者接受明确的内容，以及工业、精密或国际简约风格。它与示例制造业提供者共用模板版本固定、源码修改保护、版本历史和 ZIP 导出。发布会固定已检查内容；后续档案变化或事实过期不会自动修改网站。业务事实变化后应检查并生成新草稿。

## 本地发布

选择已保存的静态版本，点击**检查本地发布版本**，检查网站预览，确认内容可以公开，再点击**发布到当前服务**。所有 HTML 页面在发布前从已保存文件编译。缺失导入或编译后网站超限都会阻止准备。代次检查防止过期的发布或下线请求覆盖较新的状态。发布较早准备的版本可以恢复该明确版本。编辑草稿不会改变线上网站。

公开页面位于当前端口的 `/sites-live/<site-id>/`。HTML、样式、脚本和内嵌资源来自准备好的构建；源码来源记录和私有收件记录不公开提供。页面使用不透明来源沙箱，不能访问编辑器 DOM 或 Cookie。响应策略允许访问该网站的询盘路由、可选咨询路由和配置的 Umami 来源，禁止原生表单跳转。静态页面编译不会在 Host 执行生成脚本。本地发布支持包含已打包本地依赖的 HTML 页面；服务端 Next.js 执行、任意资源下载和动态服务端路由需要其他提供者。

独立的 `site-local.sqlite` 数据库保存编译版本、线上版本指针和询盘。`sites.sqlite` 仍是源码权威。对这两个数据库进行一致备份前应停止 Host。下线会停止页面访问和新询盘接收，保留历史和收件箱。关闭时先等待公开和已认证请求结束，再关闭存储。

## 询盘接收与处理

企业官网表单提交到 `/sites-live/<site-id>/_inquiries`。只有取得持久化回执后才显示成功。请求标识和内容摘要会在询盘记录保留期间对重试去重；同一标识使用不同内容会被拒绝。失败或结果不确定时保留表单内容和重试标识。私有预览或导出文件不会声称已接收询盘。

收件箱显示最近 100 条询盘和总数。获得工作空间授权的用户可以标记已读、关闭记录或永久删除。接收回执不代表已发送邮件或已同步 CRM。运营者负责回复、访问与删除请求以及保留期限。

公开接收接口刻意不要求登录。它要求 JSON、同意确认、长度受限的字段和空蜜罐字段，并执行持久化的每站每小时与总记录配额。CORS 允许沙箱访客在不携带凭据时提交，不构成发件人身份认证。面向互联网部署时可以在反向代理增加请求限制或机器人防护。此接收器不存储访客 IP 地址。

## GEO 页面与流量

企业导入生成企业、目录、产品、应用、资质、联系和隐私页面。有可用产品事实时，还生成采购指南和包含可见回答的 FAQ。Organization、WebSite、WebPage、Product 和 FAQPage 结构化数据对应可见内容；不编造缺失的价格、证书、案例或比较。发布时添加规范网址、由现成库生成的 `sitemap.xml`、`robots.txt` 和作为补充页面索引的 `llms.txt`。根 robots 列出在线网站的 Sitemap。发现内容连同公开来源固定在明确编译版本中。这些文件不保证被索引或获得 AI 引用。

流量监测使用 [Umami](https://docs.umami.is/docs/install) 的开源自托管发行版。配置服务器后，官网配置可自动创建并连接网站，也可在创建时手动填写追踪地址和网站标识。页面使用官方追踪脚本；运营中心通过 Umami API 显示浏览量、访客、访问次数、来源和事件，完整报表仍由 Umami 提供。接口故障显示不可用，不会伪装成零流量。

追踪器尊重 Do Not Track，排除 URL 片段，通过 Umami 的发送前钩子只保留 `utm_source`、`utm_medium` 和 `utm_campaign` 查询值，并把引荐地址缩减为来源。它上报浏览量和咨询、询盘事件，不发送问题、回答、表单字段或询盘标识。站内链接把归因参数带到询盘表单，无需浏览器存储。收件箱将这些字段标为访客报告，不能作为已验证身份。广告拦截与事件丢失可能造成统计不完整。持久化询盘回执仍是收件总数的权威；AI 引荐不能证明爬虫抓取或模型引用。

## 官网产品咨询

配置现有的[自托管模型路由](../../../packages/llm/llm-pi-ai/README.zh.md)，再将企业 `siteAgent` 的 `provider` 和 `model` 明确指向该路由。部署补丁通过 `DSH_SITES_AGENT_JSON` 接收此对象。企业建站时启用产品咨询。每次咨询使用发布的公开事实、新的 Harness Agent，不授予工具或工作空间提示词。请求通过现有 Session 机制记录，由运营者负责访问、保留和删除。浏览器保留有界对话历史，以纯文本呈现回答。准备询盘会将对话复制到表单；提交仍需访客明确同意。

已校验限制为 `maxTokens`（1024）、`requestTimeoutMs`（60000）、`maxQuestionsPerHour`（60）、`maxContextCharacters`（60000）和 `maxRequestBytes`（65536）。每小时用量跨重启保留，失败模型调用也计入。取消会释放请求的 Agent；发布版本变化会使等待中的回答失效。缺少配置时不能准备启用 Agent 的构建。模型不可用时仍可提交询盘。系统不会自动选择付费模型路由；本地模型安装和真实回答质量需要管理员验证。

## 网站运营

运营中心支持带版本检查的配置修改、公开内容编辑、行业/方案/案例/对比页面和翻译草稿。行业、方案和对比可依据公开产品事实生成草稿；案例成果需要单独提供已核实内容。更新企业资料会保留专题页并移除待重审翻译。手动改过源码的网站拒绝模板覆盖。保存草稿与发布是独立操作；企业投影变化时会提示检查已发布内容。

每站设置控制 SearXNG 定期搜索、ntfy 通知和 EspoCRM Lead 同步，凭据只存在 Host 配置。人工 AI 引用、本网站模型实测、搜索结果与未验证 User-Agent 抓取聚合分别标注。询盘创建同标识的企业跟进任务，重复操作返回已有任务。外部投递先持久化占用，不自动重试不确定的接收状态。CRM 可核对已有 Lead；管理员检查目标服务后可确认重试。删除本地询盘不会删除外部副本。

`DSH_SITES_SERVICES_JSON` 提供 `siteServices` 配置，字段以 [site-services.ts](../src/site-services.ts) 为准。`retentionDays` 控制定期删除搜索、引用、模型实测和抓取证据；询盘、模型 Session 与外部服务分别遵循自身策略。询盘数量与 Umami 访问次数的比值不是去重访客转化率。[自托管指南](deploy/README.zh.md)提供容器组合、私有接入、验收与备份步骤。

## 部署配置

`siteLocal` 属于企业插件配置。其已校验字段为 `maxPublicationBytes`（默认 16777216）、`maxInquiryBytes`（16384）、`maxInquiriesPerHour`（60）和 `maxStoredInquiries`（10000）。发布内容和询盘都持久化到配置的企业目录。本部署服务一个企业；不同组织需要独立进程和数据目录。

本地使用时，现有 [Trade 启动器](../../README.zh.md)在回环地址启动支持的 `dsh` profile。发布后打开 Sites 显示的地址。该进程停止后，网站和询盘接收器随之停止。

部署到企业服务器时，安装并构建同一仓库及企业插件，保留其 `templates/` 目录，首次启动时从内置 `web` profile 创建 `trade` profile，使用支持的 `dsh` CLI、[部署补丁](../../cordis.patch.yml)、持久化 `DSH_HOME` 和回环监听。在前面设置 HTTPS 反向代理，公开 `/sites-live/` 以及公开发现路由 `/robots.txt` 和 `/sitemap.xml`，并原样转发路径。不要通过该公开路由暴露 `/api/`、认证链接或工作空间界面；通过现有的已认证私有连接管理。将 `DSH_SITES_PUBLIC_URL`（企业 `publicBaseUrl`）设置为外部来源，使询盘 CSP 与访客地址一致。不要将完整本地开发工作空间当作多租户公共服务暴露。

服务器连接信息、反向代理配置和传输接口属于部署输入。本地浏览器测试不代表已上传远程服务器，也不证明公网 DNS 或 TLS 可用。

## 验证

资料投影测试覆盖可见性、核验、过期、替代关系和转义。本地发布测试覆盖固定版本、编译失败、过期代次拒绝、重启持久化、询盘去重、配额和收件归属。真实 profile 浏览器场景发布企业内容，在没有工作空间凭据的环境打开网站，模拟询盘响应丢失，无重复地重试，处理收件箱，并确认下线后公开访问被移除。增长功能测试检查发现网址、统计隔离和咨询配额。浏览器验证使用脚本化外部模型驱动真实 Harness 循环，并模拟 Umami 接口；不证明真实 Umami 部署或本地模型质量。
